# Bite Shore
Bite Shore

Bite Shore — вебзастосунок для аналізу погодних умов і формування рекомендацій щодо риболовлі.
Проєкт складається з backend на Java та Spring Boot і frontend на HTML, CSS та JavaScript. 
Застосунок отримує погодні дані, зберігає їх у PostgreSQL, аналізує погодні умови та формує рекомендації для вибраного 
місця й дати риболовлі.

Можливості:
Аналіз погодних умов для вибраного місця та дати риболовлі.
Отримання погодних даних за географічними координатами або назвою міста.
Аналіз атмосферного тиску, температури, вітру й опадів.
Розрахунок орієнтовної температури води.
Урахування сезонних умов і температурних змін.
Формування загальних рекомендацій щодо риболовлі.
Відображення результатів у вигляді інформаційних карток.
Збереження погодних даних та використання їхньої історії для аналізу.
Запуск застосунку через Docker Compose.

Main Components

Weather
WeatherAPIClient — отримує погодні дані із зовнішнього Weather API.
WeatherService — обробляє отримані погодні дані.
WeatherMapper — перетворює дані зовнішнього API у внутрішні об'єкти застосунку.
WeatherOrchestratorService — керує процесом отримання та збереження погодних даних.
WeatherStorageService — відповідає за збереження погодних даних у базі даних.
WeatherHistoryService — завантажує збережені погодні дані для подальшого аналізу.

Aggregators

Агрегатори об'єднують та узагальнюють погодні дані, формуючи показники, необхідні для подальшого аналізу.

Основні агрегатори:
TemperatureAggregator
PressureAggregator
WindAggregator
PrecipitationAggregator

Кожен агрегатор відповідає за обробку даних певного погодного параметра. 
Результати їхньої роботи використовуються відповідними аналізаторами.
Агрегатори відокремлюють підготовку погодних даних від логіки оцінювання умов риболовлі.

Analyzers

Аналізатори оцінюють погодні параметри та визначають відповідні стани погодних умов.

Основні аналізатори:

TemperatureAnalyzer
PressureAnalyzer
WindAnalyzer
PrecipitationAnalyser
GeneralAnalyzer

GeneralAnalyzer отримує результати окремих аналізаторів та на їх основі формує загальну рекомендацію щодо риболовлі.
Результат передається у FishingAnalysisResponse для повернення клієнту.

Fishing Analysis

Для аналізу користувач передає:

широту (latitude);
довготу (longitude);
місто (city);
дату риболовлі (fishingDate).

Для отримання погодних даних можуть використовуватися географічні координати або назва міста.

Основний процес:

FishingAnalysisService отримує запит.
WeatherOrchestratorService організовує отримання погодних даних.
Дані отримуються із зовнішнього Weather API.
Погодні дані зберігаються у PostgreSQL.
WeatherHistoryService завантажує дані, необхідні для аналізу.
Агрегатори формують узагальнені погодні показники.
Аналізатори оцінюють окремі погодні параметри.
GeneralAnalyzer формує загальну рекомендацію.
Результат повертається клієнту.

Weather Analysis

Застосунок аналізує такі погодні фактори:

температуру повітря;
атмосферний тиск;
швидкість і пориви вітру;
опади;
температуру води;
зміни температури;
сезонні умови.

На основі цих параметрів визначаються стани погодних умов та формується рекомендація щодо риболовлі.

Temperature Analysis

Аналіз температури враховує:

денну температуру;
нічну температуру;
середню температуру;
температуру попередніх днів;
температурний тренд.

Якщо нічна температура відсутня, для розрахунку використовується доступна денна температура.
Результати аналізу використовуються для оцінювання температурних умов для риболовлі.

Water Temperature

Температура води розраховується на основі погодних даних та попереднього значення температури води.
Якщо попереднє значення відсутнє, використовується початкова оцінка на основі середньої температури повітря.
Для наступних розрахунків враховуються попереднє значення температури води та поточна температура повітря.
Розрахована температура води використовується під час оцінювання температурних умов для риболовлі.

Pressure Analysis

Атмосферний тиск оцінюється відносно заданого базового значення.
Поточна логіка використовує такі стани:

Тиск

Стан:
Менше 752
LOW

Від 752 до 758 включно
NORMAL

Більше 758
HIGH

Також враховується зміна атмосферного тиску відносно попередніх значень.

Wind Analysis

Для оцінки впливу вітру враховуються:

швидкість вітру;
пориви вітру;
наближеність дати прогнозу до дати риболовлі;
напрямок вітру та його вплив на рекомендації.

При оцінюванні використовується комбінований показник швидкості вітру та поривів.
Для прогнозів на віддалені дати враховується додатковий запас під час оцінювання умов.

Precipitation Analysis

Опади поділяються на стани залежно від їхньої інтенсивності:

NONE
LIGHT
MODERATE
HEAVY

Інтенсивність опадів враховується під час формування загальної рекомендації.
Опади також можуть впливати на оцінку температурних умов.

Database

Для зберігання погодних даних використовується PostgreSQL.

Основні параметри:

Database: PostgreSQL
Port: 5432
Database name: bite_short

Для роботи з базою даних використовуються Spring Data JPA та Hibernate.

Поточна стратегія автоматичного оновлення структури бази даних:

spring.jpa.hibernate.ddl-auto=update

Основні таблиці:

weather_data
weather_location

REST API

Основний endpoint для аналізу риболовлі:

POST /api/fishing/analyze

Request

{
"latitude": 48.4647,
"longitude": 35.0462,
"city": "Дніпро",
"fishingDate": "2026-11-05"
}

Response

{
"fishingDate": "2026-11-05",
"recommendation": [
"Приклад першої рекомендації",
"Приклад другої рекомендації"
]
}

Приклад демонструє структуру запиту та відповіді. 
Фактичний вміст рекомендацій залежить від погодних даних та результатів аналізу.

Validation

Дата риболовлі не може бути в минулому.
Дата риболовлі не повинна виходити за встановлений горизонт прогнозування.
Для визначення місця прогнозу можуть використовуватися координати або назва міста.

Environment Variables

Для доступу до зовнішнього Weather API використовується змінна середовища:

API_KEY
При запуску через Docker Compose значення передається через файл .env.
Приклад вмісту .env:
API_KEY=your_api_key
Заміни your_api_key на власний ключ API.
Файл .env не повинен публікуватися у Git-репозиторії, оскільки він може містити секретні дані.

Docker Compose

Для запуску застосунку разом із PostgreSQL та Nginx використовується Docker Compose.

Основні компоненти:

Docker Compose
├── app
│   └── Spring Boot
├── db
│   └── PostgreSQL 17
└── nginx
└── Frontend / Reverse Proxy

Застосунок підключається до PostgreSQL через ім'я сервісу Docker Compose:

jdbc:postgresql://db:5432/bite_short

Для збереження даних PostgreSQL використовується Docker Volume. 
Це дозволяє зберігати дані після перезапуску або пересоздання контейнерів.

Running with Docker Compose

Для запуску необхідні:

Docker Desktop;
файл compose.yml;
налаштовані змінні середовища у .env.

Запуск контейнерів:
docker compose up -d --build

Перевірка стану контейнерів:
docker compose ps

Перегляд логів застосунку:
docker compose logs -f app

Зупинка контейнерів:
docker compose down

Команда docker compose down без параметра -v не видаляє іменовані томи PostgreSQL, тому дані зберігаються.

Accessing the Application

Після запуску відкрий у браузері:

http://localhost

Це посилання працює на комп'ютері, де запущений Docker Compose, за умови що Nginx опублікований на порту 80.

Docker Hub Image

Отримати готовий Docker image можна командою:

docker pull student78/bite-shore:1.0

Для запуску готового image не потрібно переносити вихідний Java-код або Dockerfile. 
Водночас для роботи застосунку необхідно налаштувати підключення до бази даних, змінні середовища та інші залежності.
Running Locally

Для локального запуску без Docker необхідно:
Встановити Java 21.
Встановити Maven.
Запустити PostgreSQL.
Створити базу даних bite_short.

Налаштувати змінну середовища API_KEY.
Запустити Spring Boot застосунок.
Backend запускається на порту:
8080
